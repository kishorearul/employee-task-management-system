# Interview Preparation

## 1. Project explanation (30-second pitch)

"An enterprise Employee Task & Project Management API: departments group employees;
managers own projects; projects contain tasks assigned to employees. JWT auth with
ADMIN/MANAGER/EMPLOYEE roles enforced in the backend. FastAPI + PostgreSQL +
SQLAlchemy + Alembic + pytest + Docker, with a small vanilla-JS frontend."

## 2. Architecture

Client → Router (thin) → Service (business rules) → Repository (SQL only) →
SQLAlchemy → PostgreSQL. Schemas validate at the boundary. Reusable auth
dependencies inject the current user / enforce roles. Centralized error handlers
return consistent JSON without leaking internals.

## 3. Why FastAPI?

Auto OpenAPI/Swagger docs, Pydantic validation, dependency injection, async-ready,
type-hint driven, high performance for I/O-bound APIs. Faster to build correct
CRUD than Flask/Django for this use case.

## 4. Why PostgreSQL?

ACID, FK enforcement, constraints/indexes, ENUMs, production-grade reliability;
SQLite fallback keeps local dev/tests zero-setup via the same SQLAlchemy code.

## 5. Why SQLAlchemy 2.x?

Mature ORM: relationships, lazy loading, migrations via Alembic, DB-agnostic
(switch SQLite↔Postgres by URL). `mapped_column` style is type-checker friendly.

## 6-7. Authentication / JWT

Passwords hashed with bcrypt (via pwdlib) — never plaintext. Login verifies the
hash and returns a signed JWT (`sub`=user id, `exp`=expiry). Clients send
`Authorization: Bearer <token>`; `get_current_user` decodes and loads the user.
PyJWT + pwdlib chosen because python-jose/passlib are unmaintained.

## 8. RBAC

`require_roles(...)` dependency factory; e.g. `Depends(require_roles(ADMIN))`.
Employees updating tasks go through `task_service.update_task`, which allows only
`status` on their own assigned tasks (ownership resolved via
`employees.user_id == current.id`). Frontend buttons are convenience only —
the backend returns 403 for violations.

## 9. Relationships

- Department 1—N Employee; User 1—1 Employee profile (user_id unique);
- User 1—N Project (manager); Project 1—N Task (cascade delete);
- Employee 1—N Task (assignee); User 1—N Task (creator audit).
Indexes on FKs + unique on username/email/department name/employee email.

## 10. API highlights

RESTful resources, correct status codes (201 create, 204 delete, 400/401/403/404/409/422),
pagination (`skip/limit`), task filters (status/priority/project/assignee),
`GET /projects/{id}/progress` computed live (never stored).

## 11. Important SQL (generated by the ORM)

```sql
-- login lookup
SELECT * FROM users WHERE username = 'admin';
-- employees in a department
SELECT * FROM employees WHERE department_id = 1 LIMIT 100 OFFSET 0;
-- filtered tasks
SELECT * FROM tasks WHERE status = 'TODO' AND project_id = 2;
-- dashboard counts
SELECT COUNT(*) FROM tasks WHERE status = 'COMPLETED';
-- progress inputs
SELECT id, status FROM tasks WHERE project_id = 1;
```

## 12. Python concepts used

OOP (models/services as classes/functions with single responsibility), type hints,
enums, dependency injection, decorators (`@router.get`, validators), context
managers (DB session yield), comprehensions (progress counts), layered modules,
custom exceptions, logging, fixtures (pytest).

## 13. Possible interview questions

- Router vs service vs repository — why separate?
- Where is RBAC enforced and how would you add a new role?
- How does JWT auth work end-to-end? Where is the secret stored?
- Why hash passwords with bcrypt (salt, work factor)?
- How do you prevent duplicate emails/departments? (DB unique + service 409)
- How is project progress calculated and why not stored?
- How do Alembic migrations work? Why not `create_all` in prod?
- How do tests isolate the DB? (override `get_db`, fresh SQLite per test)
- How would you add pagination metadata / refresh tokens / audit logs?

## 14. Coding questions you could get

- "Add task comments" → new model + FK + router/service/test.
- "Only the managing manager may edit their project" → check `project.manager_id == current.id`.
- "Prevent assigning tasks past the project deadline" → compare dates in `create_task`.
- "Return tasks with assignee name in one query" → `joinedload(Task.assignee)`.

## 15. Bugs encountered and fixes

- Pinned `psycopg`/pydantic wheels failed on Python 3.14 → relaxed pins to `>=`.
- Alembic `sa.Column(sa.Enum(...))` without a name → added explicit column names.
- Tests got 422s because fixtures used 1-char names/titles vs `min_length=2` → fixed fixtures.
- `KeyError: 'id'` cascades were caused by the same 422s → fixed by above.

## 16. Possible improvements

Refresh tokens, httpOnly cookies, pagination metadata, full-text search, task
history/comments, notifications, CI, rate limiting, caching of dashboard counts.
